Alpha · Metal on Apple Silicon · one machine's numbers

GPU kernels that say what they can do.

Write a tile kernel once. The compiler checks it, refuses what is wrong and names the rule, and writes CUDA C and Metal. The same kernels run text, image, video and speech models on a Mac's GPU.

Try itSee the evidence

Refuses wrong programs

Every tile is consumed exactly once; bounds, shapes and the threadgroup budget are checked, and a refusal names the rule it broke.

One source, two targets

The same .chx kernel becomes CUDA C and Metal. Every emitted text is held byte for byte to a recorded golden: 499 cases.

Held to numbers

Each numeric kernel is checked against a float64 reference written from the mathematics, and each model against its reference implementation.

An authority you can read

The compiler links only libc. Its report lists what it may do (files, printing, memory), and the gate fails if that widens. No network, no foreign code.

What the promise does not establish: that a kernel is fast (speed is measured, and the table below has the rows where others are faster), that CUDA works beyond the one NVIDIA L4 it ran on, or that a kernel computes what you meant (the checker proves linearity, bounds and shapes, not intent).

Shows: the refusal and its stable rule tag (rules.md). Does not show: that a kernel which passes computes what you meant.

Shows: Qwen3-ASR-1.7B on the GPU, giving the reference's transcript to the letter on its two clips, 16.2 s of speech in 3.0 s from a cold start (audio.md). Does not show: a word error rate on a test set, or clips over 152 s, which are refused.

How it works.

A kernel is checked before it is lowered; a refusal never reaches a GPU. The CPU interpreter is the reference for what a kernel computes.

// a = silu(g) * u over a row of n: the gated activation of a SwiGLU MLP.
algo swiglu(n)
  in  g: f32[1, n]
  in  u: f32[1, n]
  out y: f32[1, n]
{
  let gt = load g
  let ut = load u
  let sg = sigmoid &gt
  let a  = gt * sg
  store a * ut -> y
}

schedule swiglu for apple-m-series { threads 256 }
schedule swiglu for nvidia-ada     { threads 256 }
kernel void swiglu_17408(
    device const float* p0_g [[buffer(0)]],
    device const float* p1_u [[buffer(1)]],
    device float* p2_y [[buffer(2)]],
    uint tid [[thread_index_in_threadgroup]],
    uint3 tgpos [[threadgroup_position_in_grid]])
{
    const uint gid = tgpos.x;
    float v2[68];
    for (uint k = 0; k < 68u; ++k) {
        const uint e = k * 256u + tid;
        if (e < 17408u) {
            v2[k] = float(1.0f / (1.0f + precise::exp(-float(float(p0_g[(uint)(0) * 17408u + (uint)(0) * 1u + ((e))])))));
        }
    }
    float v3[68];
    for (uint k = 0; k < 68u; ++k) {
        const uint e = k * 256u + tid;
        if (e < 17408u) {
            v3[k] = float(float(float(p0_g[(uint)(0) * 17408u + (uint)(0) * 1u + ((e))])) * float(v2[k]));
        }
    }
    float v4[68];
    for (uint k = 0; k < 68u; ++k) {
        const uint e = k * 256u + tid;
        if (e < 17408u) {
            v4[k] = float(float(v3[k]) * float(float(p1_u[(uint)(0) * 17408u + (uint)(0) * 1u + ((e / 1u))])));
        }
    }
    for (uint k = 0; k < 68u; ++k) {
        const uint e = k * 256u + tid;
        if (e < 17408u) {
            p2_y[(uint)(0) * 17408u + (uint)(0) * 1u + (e)] = float(float(v4[k]));
        }
    }
}

    const float* __restrict__ p1_u,
    float* __restrict__ p2_y

    }
    float v3[68];
    for (uint k = 0; k < 68u; ++k) {
        const uint e = k * 256u + tid;
        if (e < 17408u) {
            v3[k] = float(float(float(p0_g[(uint)(0) * 17408u + (uint)(0) * 1u + ((e))])) * float(v2[k]));
        }
    }
    float v4[68];
    for (uint k = 0; k < 68u; ++k) {
        const uint e = k * 256u + tid;
        if (e < 17408u) {
            v4[k] = float(float(v3[k]) * float(float(p1_u[(uint)(0) * 17408u + (uint)(0) * 1u + ((e / 1u))])));

What exists today, and what does not.

Built

  • The compiler: parser, checker, CUDA C and Metal emitters, a CPU interpreter, and device paths for both targets
  • Qwen3.8-27B served over /v1/chat/completions, with streaming, a prefix cache and the model's own draft head
  • Text to image and photo editing (Qwen-Image-2.1-Turbo), video from a prompt (FastWan2.2-TI2V-5B), speech to text (Qwen3-ASR-1.7B), through scripts/media
  • Training on the GPU: a GPT, a CNN, Qwen2.5 with LoRA and full fine-tuning, each held to torch or peft

Not yet

  • CUDA beyond one NVIDIA L4 run of an earlier suite; no Hopper, no AMD
  • Any number from a second machine: everything here is one Apple M4 Max
  • Concurrent requests, tools and stop sequences in the server
  • An image as fast as mflux's, prose as fast as Ollama's, a CNN step as fast as torch's
  • Speech synthesis (the decoder's kernels are being built) and music

Measured, not promised.

Who ran what. Every time above was measured by hand on one Apple M4 Max (64 GB), not by CI. Text: each engine alone, greedy, the fastest of three runs, Ollama after it had warmed (serving.md 11.6). Image and video: each engine a new process, run in turn; the pictures were not compared between engines (diffusion.md 8). Training: one run and one seed each, with loss curves equal to torch's or peft's to the digits given there (resident.md). Where a claim turned out false, the document that made it was corrected in place.

Try it.

You need the cancho compiler release pinned in cancho.toml (a prebuilt download, no Rust). The compiler runs anywhere; the models need a Mac with Apple Silicon.

git clone https://github.com/alpibrusl/cancho-gpu && cd cancho-gpu

curl -fsSL https://raw.githubusercontent.com/alpibrusl/cancho/main/scripts/install.sh | sh -s "$(sed -n 's/^cancho *= *"\([0-9a-f.]*\)".*/\1/p' cancho.toml)"    # the release CI uses
export CANCHO=$HOME/.local/bin/cancho

$CANCHO build
mkdir -p out
build/cancho-gpu emit tests/chx/softmax.chx out r=16 n=256

Then cancho-gpu check <file.chx> [name=value ...] [--run] for the checker and the interpreter, scripts/media doctor for what the models need, and scripts/gate.sh for everything CI runs.

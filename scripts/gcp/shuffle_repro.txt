# Status: both bugs are fixed in the CUDA emitter (the lookup is `FP4_V[nibble]`, PR #104), and the fix is CHECKED ON
# HARDWARE: on a real NVIDIA L4 (g2-standard-8, europe-west1-b) these 50 cases were 7 PASS / 3 MISMATCH / 40 TIMEOUT before the
# fix (run 20261104-212332-l4) and are 50 PASS, no mismatch or timeout, after it (main 46670b5, run 20261105-083519-l4; the step took
# 20 s, was 2413 s). So every line below should PASS here; a non-PASS is a regression or a new bug. Each line runs through build/cancho-gpu-device on the GPU against the interpreter,
# 60 s, its own process. PASS on a GPU does not clear a bug the CUDA guide calls
# undefined; MISMATCH / TIMEOUT / ERROR is the bug seen on hardware.

# Bug 1: `__shfl_sync(0xffffffffu, fp4_lane, nibble)` inside a per-lane loop
# `for (p0 = lane; p0 < K; p0 += 32)` with K = 16 mod 32: lanes 0..15 take one more trip
# than 16..31, so the full mask names lanes that left the loop (undefined; emulator: deadlock).

tests/chx/matvec_fp4.chx n=2 k=80                      # bug 1, per-lane loop in a block with barriers

# Bug 2: the same shuffle in the element-per-thread fallback (`if (e < count)`), count not a
